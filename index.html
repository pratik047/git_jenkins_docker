🔄 How the Pipeline Works

1

Push Code

Developer updates index.html or Dockerfile and pushes the changes to GitHub.

2

Trigger Jenkins

The GitHub webhook notifies Jenkins to start the configured job.

3

Pull Code

Jenkins fetches the latest files from the GitHub repository into its workspace.

4

Build Docker Image

Docker reads the Dockerfile, uses nginx:alpine, and copies index.html into Nginx's web directory.

docker build -t myimage .

5

Run Container

Jenkins replaces the old myweb container if present, then starts a new one on port 8081.

docker run -d -p 8081:80 --name myweb myimage

6

Access Website

Nginx serves index.html from the running container to the user's browser.

🌐 Final Output — Your Website

When the Jenkins build succeeds, open the application hosted on EC2 Instance 2.

http://YOUR-JENKINS-EC2-PUBLIC-IP:8081

Hello from Jenkins and Docker!

Replace the placeholder with the public IP of your Jenkins EC2 instance.

⚠️ Important:

Ensure the Jenkins EC2 Security Group allows inbound TCP port 8081 from your IP address. Jenkins must have Docker permissions, and index.html must exist in the root of the GitHub repository beside the Dockerfile. The GitHub webhook must be configured and reachable.
